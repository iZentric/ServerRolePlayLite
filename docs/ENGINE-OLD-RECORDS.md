# Corecție: barele istorice RAM/boot NU erau benchmark A/B

Pe site apăreau `CUANTIC 1.7.7: 2643 MB · Done 11.521s` și `CatServer oficial + Java 17: 2814 MB · Done 11.062s`, cu podium 👑/🥈. Valorile provin din `site/records.json`, unde generatorul lua **separat minimul RAM și minimul de boot** din runde potențial diferite. Fișierele-sursă `analysis/test-boot-CatServer-CUSTOM*.md` și `analysis/test-boot-CatServer-J17.md` nu sunt în checkout-ul curent, astfel că nu se mai poate verifica identitatea mașinii, pack-ului, seedului, încălzirii, JVM-ului sau momentul probei. `Done` nu este nici timpul complet până la intrare.

**Nu rezultă un avantaj de 171 MB (≈6,1%) pentru CUANTIC.** Nu există o pereche controlată sau interval de eroare; chiar și cele două recorduri de boot citate arată 11.521 vs 11.062 s, nu un câștig la pornire. Am scos podiumul și barele din site, nu am transformat minimele în medii. `site/records.json` rămâne arhivă necomparabilă și nu mai alimentează pagina.

Comparația corectă cere *același runner în același job, Java 17 identic, aceeași arhivă cu 36 moduri/14 pluginuri, aceleași setări și comenzi*, mai multe porniri în ordine A/B/B/A, SHA pentru fiecare JAR, RSS în aceeași fereastră stabilă, CPU și p95 pe sarcină identică. Un scenariu fără jucători/vehicule nu dovedește optimizarea RP în joc. [Benchmarkul actual al fork-urilor](BENCHMARK-MOTOARE-CUANTIC-2026-10-12.md) are metode diferite, dar valide în interiorul fiecărei comparații; noul test CatServer oficial vs binarul CUANTIC trebuie raportat separat.
