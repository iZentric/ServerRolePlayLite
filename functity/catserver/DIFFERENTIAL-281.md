# Poarta diferențială 281 — contracte publice, NU produs RP validat

[Presupus] „281 differential harnesses” = **281 scenarii distincte** într-o poartă reproductibilă; în cod sunt **două mecanisme de test**, nu 281 programe și nu 281 simulări de clienți. Nu cosmetizăm numărul: [20 de cazuri Java 11 pe metodele efective](../../scripts/fc_funcity_bridge_java_contract.py) extrase din CatServer pin-uit cu patchurile `0002`/`0003`, plus [261 de cazuri de model pentru pachete](../../scripts/fc_differential_281.py) rulate de [harnessul JNI/Java](../../experiments/packet-compression/PacketDifferential281.java). [Workflowul](../../.github/workflows/funcity-differential-281.yml) oprește verdictul dacă lipsește un caz, un mutant Forge nu e respins, un stream nu poate fi decomprimat identic ori apare o divergență de prag.

## Ce diferențiază efectiv

| Domeniu | Referință / candidat | 281: ce se verifică | Ce NU se verifică |
|---|---|---|---|
| Forge→Bukkit place/multiplace/break | Comportamentul permis de upstream vs patchurile proprii: aceeași decizie când Forge permite, păstrarea veto-ului Forge când Bukkit dezanulează | 16 combinații place/multiplace (Forge/Bukkit/canBuild), 4 break (Forge/Bukkit), callback, XP, drop și **doi mutanți fără veto respinși**, pe metode Java reale cu tipuri simulate | Evenimente reale ale 34/13, CoreProtect, world save, compatibilitatea altor moduri/pluginuri |
| Prag/VarInt/zlib (model explicit, **nu clasa Netty reală**) | Java 11 `Deflater` reutilizat vs JNI către C libdeflate MIT pin-uit; streamurile diferite sunt permise dacă datele decomprimate coincid | 64 lungimi × 4 tipare (zero, repetitiv, pseudoaleator, mixt) la prag 256 = 256 cazuri; +5 margini (zero-length, praguri 0/1/512, 2 MiB) = **261**. Jumătate din matrice folosește sursă directă, jumătate heap; se verifică frame-ul, lungimea, pragul, zlib fără bytes extra, inputul original și respingerea unui header corupt. | ByteBuf real / buffers compozite, dimensiuni reale ale pachetelor, Forge handshake, Netty concurrency, auth, voice, 34/13, CPU/RSS sau jucători. Native **nu** este în server.jar. |

Această probă este de **corectitudine a contractului modelat**, nu 281 benchmarkuri de performanță. Nu citește date private, nu publică JAR-uri și nu atinge serverul. Pentru protocolul actual, valoarea lungimii este VarInt; după header `0` urmează date necomprimate sub prag, iar după un header pozitiv urmează streamul zlib cu lungimea necomprimată declarată. Oracle-ul Java `Inflater` verifică și lipsa datelor zlib suplimentare. Un stream zlib byte-identic nu este cerut (algoritmii pot alege niveluri/blocuri diferite).

## Comparația a cel puțin trei opțiuni; nu copiem „tot ce are altul” automat

| Candidat | Avantaj posibil | Cost/semnificație pe 2 vCPU, Forge+Bukkit 1.16.5 | Decizie reversibilă |
|---|---|---|---|
| **CatServer oficial** | Contractul hibrid existent și sursa compatibilă de bază | FunCity este derivat din aceeași sursă; X vs oficial a fost practic egal sau oficialul a condus la CPU în probe publice 18/6/0 clienți. | Referință obligatorie pe copia completă; patchurile `0002`/`0003` sunt corectitudine, nu câștig de capacitate. |
| **Paper / Folia** | Optimizări în motor, respectiv paralelism regional | Paper nu încarcă JAR-urile Forge 1.16.5; Folia necesită adaptări plugin și recomandă ideal ≥16 nuclee, nu 2 vCPU. | Studiem mecanismele și compatibilitatea/licența; nu transplantăm schedulerul. |
| **Starlight / Chunk Sending** | Lumină / traseul chunkurilor separat | Testul public de iluminare Starlight a redus CPU, dar a crescut RSS; combinația a trecut numai boot 20/6/0 clienți. | Se adaugă pe *copii TEST diferite*, se verifică formatul lumii, gameplay și clientul, nu se „absorb” automat în motor. |
| **Java existent / JNI libdeflate** | Java nu adaugă risc nativ; JNI a fost mai rapid în microbenchuri publice | Compresia Netty 34/13 încă nu a fost identificată ca hotspot; diferențele de buffer model nu demonstrează capacitate. | Java rămâne baseline; JNI numai opt-in cu fallback după profilul privat și A/B integrat. |
| **Rescriere completă Rust** | Libertate de arhitectură | Nu există dovadă de încărcare a ABI Forge+Bukkit și a lumii RP existente. | Cercetare separată, nu înlocuitor prezentat drept produs compatibil. |

Regula de adoptare: un motiv pentru care alt motor e mai bun trebuie identificat **sub același workload** (CPU, p95/p99, RSS, trafic, compatibilitate), verificat licența/API-ul și izolat ca singura modificare în A/B/B/A pe copie. Îl păstrăm numai dacă trece scenariile RP și crește o treaptă de jucători 2/2 când referința eșuează 2/2, fără regresii. Dacă nu, rămâne la referință. Combinarea tuturor optimizărilor nu garantează un maxim; unele consumă RAM sau schimbă semantica.

**Poartă care rămâne deschisă:** [H2–H6](GOALS.md) cer lumea privată, inventarul 34/13, clienți Forge, voice/auth/vehicule, profil CPU, 2 vCPU/12 GB verificați, backup inclusiv extras, restore și rollback. Jobul de resurse TEST este încă în așteptare. **281 cazuri publice trecute ≠ 281 harnessuri diferențiale end-to-end și ≠ produs final.**

**Test adversarial al limitei native:** prima execuție [41587394760](https://github.com/iZentric/ServerRolePlayLite/actions/runs/41587394760) a eșuat la `JNI zlib unavailable or buffer too small` în noua matrice; vechiul `input + 1024` nu reprezenta un bound garantat pentru toate cazurile. Am schimbat alocarea în cercetare la `libdeflate_zlib_compress_bound()` prin JNI și am adăugat o respingere explicită pentru ieșire sub bound; diagnosticul complet așteaptă rerularea. Fără integrare în motor.
