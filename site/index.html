De ce exact 36 moduri — și niciunul „la întâmplare"

Regula pack-ului: un mod intră pe server DOAR dacă binarul poate fi potrivit cu sursa lui (repo + commit/tag + SHA). Candidați testați și respinși onest:

CandidatCe aduceaDe ce NU e pe server
KryptonReforgednetty 4.1 pe Forgeam încercat build din source @ forge-1.16 — esueaza pe dependinta curse.maven:magnesium (maven mort din 2020); singurul jar e pe CurseForge, nepotrivit cu niciun commit public; plus coliziune cu patch-ul netty propriu al Mohist (fișa FISE)
Starlight (Forge)iluminare de 7x mai rapidă la chunk-genportul 1.16.5 fără repo verificabil prin API; pe puntea Mohist e „zona periculoasă" conform fișei — refuzat pentru ca nu-i putem semna proveniența
RandomPatchesreparații RNG/leaks2.4.4 publicat doar ca arhivă CF, SHA de manifest negăsit pe sursă; functional acoperit deja de memoryleakfix+FerriteCore din pack

Runda asta a însemnat și un build real în CI (pack-build.yml, commit pinat) — a eșuat din cauza dependency-ului mort al autorului, dovada că nu e vină de lene. Cine dă binar „mai bun" cu SHA de git = intră în staging (mod packtest) și iese singur dacă strică ceva (packpromote cu rollback la 300 s).

Setări recomandate pe client slab

  • Java 11, alocare -Xmx3G (nu mai mult — se chinuie garbage-collector-ul)
  • Render distance 6–8, Graphics Fast, VSync on, Particles minimum
  • Biological/island nu contează; Biome blend 0
  • Sub 30 FPS? doar atunci OptiFine, peste rest — nu în loc de ModernFix
