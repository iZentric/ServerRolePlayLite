## Capacitatea REALĂ a hostului și memoria observată pe PC

Captura Startup trimisă de proprietar arată **3 GiB RAM**, **15 GiB disc** (59,41 MiB folosiți), plafon afișat **200% CPU**, server offline, comandă de pornire `java ... -jar server.jar` și opțiuni de imagine Java 8–26, cu „Default - Java 25” în listă. Acestea înlocuiesc *ipoteza de planificare* 12 GB RAM / 2 CPU din documentele istorice: nu pretinde că planul actual are 12 GB. Comanda afișată rezervă implicit 704 MiB în afara heapului, deci la 3 GiB și `MEMORY_OVERRIDE=0` calculează maxim **2368 MiB heap** (`3072-704`), nu 3 GiB de heap; nu crește `-Xmx` peste RAM-ul planului. Proprietarul a confirmat selectarea Java 11; agentul nu poate citi selecția prin SFTP. Prima pornire a produs un log cu `Done`, dar nu dovedește starea curentă sau încărcarea RP.

Riscul de OOM este real; înainte de instalare trebuie un boot izolat cu copia completă, memorie plafonată și teste de gameplay sau un plan mai mare. Nu cumpăra resurse și nu presupune că 3 GiB sunt suficiente pe baza acestor cifre.
